# ショットマップ（商用版MVP・仮称）

番手と狙いを選ぶと、自分の球がどこに落ちそうかを航空写真の上に確率範囲で表示するPWA。
個人用版（`../golf`）とはコード・データ・保存領域を完全に分けた別アプリ。

## 個人用版との違い

| | 個人用版 | 商用版MVP |
|---|---|---|
| ばらつきの元 | TOPTRACERの練習データ（CSV） | **自己申告**（平均スコア・飛距離・曲がり傾向）→ **ラウンド中の1タップ記録**で本人の分布へ寄せる。CSVは上級者向けオプション |
| コース | 木曽駒のみ | 住所検索・現在地からコースを追加、ホールはタップで登録（木曽駒はサンプル） |
| 競技対応 | なし | 競技モード（距離のみ表示。高低差・風の補正、ばらつき予測、おすすめ番手を非表示） |
| 航空写真 | 国土地理院 / Esri | 国土地理院のみ（出典表示で商用利用可） |
| 気温 | 手入力 / Open-Meteo自動取得 | 手入力のみ（Open-Meteoの無料枠は非商用限定のため） |
| 保存キー | `golfplan.*` | `golfcm.*`（同じドメインでも衝突しない） |

## 使い方の流れ

1. 初回設定（1〜2分）: 注意事項の確認 → 平均スコア → バッグのクラブ → 飛距離（1Wと7Iを入れて「自動で埋める」→ 微修正。キャリー/トータル選択可）→ 曲がり傾向（全体・ドライバー）
2. コースとホールを選ぶ（未登録ホールはティー→グリーン中心をタップして登録）
3. 番手を選び、狙いをタップ → 確率範囲（50/80/95%）を表示
4. 打ったら「📍結果を記録」→ ボールが止まった位置をタップ。次の打つ位置も自動でそこに移る（取り消し可）

## 計算モデル

- **推定（自己申告）**: 平均スコアから番手共通のばらつき（左右・前後のブレ、大ミス率）を決め、番手の種類（ドライバー〜ウェッジ）で倍率をかける。曲がり傾向の側に平均をずらし、大ミスもその側に出やすくする（`js/prior.js`）
  - ⚠️ スコア帯ごとの数値は**仮の初期値**。リリース前に実データで校正が必要
- **実データ**: ラウンド記録・CSVのショットを、標準大気（海抜0m・15℃）・平地のキャリーに換算して保持（記録は止まった位置までの距離×番手別キャリー比率で、ランを差し引く）
- **混ぜ方**: 1球ごとに確率 `priorStrength / (priorStrength + 実効球数)` で推定から、それ以外は実データ（カーネル密度推定）から引く。既定 priorStrength=10（推定を10球分とみなす）。直近重視の半減期90日
- **状態表示**: 記録5球未満=推定、5〜19球=学習中、20球以上=実データ
- 補正（個人用版と同じ）: 打つ位置の標高と気温による空気密度、風、着弾点ごとの高低差（落下角で換算）
- 確率範囲は点群の密度から作る最高密度領域（大ミスの塊は別の島として表示）

## ファイル構成

| ファイル | 役割 |
|---|---|
| `js/clubs.js` | 番手の定義・表示名（ウェッジはロフト角）・飛距離の目安比率・キャリー比率・落下角 |
| `js/prior.js` | 自己申告からの推定分布（スコア帯別パラメータ） |
| `js/model.js` | 実データの標準化、推定と実データの混合サンプリング、補正、CSV解析 |
| `js/courses.js` | コースの追加・削除・ホール保存、住所検索 |
| `js/app.js` | 画面・地図・初回設定・記録・設定 |
| `js/contour.js` `js/dem.js` `js/geo.js` `js/store.js` | 確率範囲の輪郭、標高、座標計算、保存（個人用版からコピー） |
| `sw.js` | オフライン（キャッシュ名は `shotmap-` で始め、他アプリのキャッシュは消さない） |

## ローカル起動

```bash
python -m http.server 8766
```

http://localhost:8766 を開く。

## 公開時の注意

- **個人用版と同じドメイン（例: `yohei-slot.github.io`）に置かないこと。** 個人用版の Service Worker は更新時に自分以外のキャッシュを削除するため、商用版のオフラインデータが消える。別ドメイン（別アカウントの GitHub Pages、Cloudflare Pages など）で配信する

## リリースまでに残っている課題

- スコア帯別ばらつきの校正（ラウンド記録の集計など、自社で集めたデータで）
- 利用規約・プライバシーポリシー・特定商取引法の表記
- 国土地理院の住所検索APIの利用条件の確認（商用・アクセス量）
- アカウントとクラウド同期（今は端末内保存＋バックアップファイルのみ）
- ネイティブアプリ化の検討（ストア配信、課金、バックグラウンドGPS）
- コースデータの整備方法（ユーザー登録の共有、データ購入など）
- 競技モードの規則解釈の確認（JGA/R&Aの見解）
